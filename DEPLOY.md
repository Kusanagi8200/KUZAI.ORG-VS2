## DEPLOYMENT WORKFLOW

GitHub is the source of truth for production.

The production server should not be used as the normal place to create commits. Validated changes are committed to the GitHub repository first, then the server is synchronized from `origin/main`.

From the production server:

```bash
cd /var/www/kuzai.org
git fetch origin
git status --short
git pull --ff-only origin main
```

After synchronization:

```bash
git rev-parse --short HEAD
git rev-parse --short origin/main
git status --short
```

Expected state:

- local `HEAD` equals `origin/main`;
- `git status --short` is empty;
- no implicit merge commit is created.

If the working tree contains local changes, inspect them before any reset, checkout or pull.

## PUBLIC APPLICATION DEMO

Public URL:

```text
https://kuzai.org/demo/
```

Presentation page:

```text
https://kuzai.org/index.php?page=application-demo
```

The public demo is intentionally separate from the private KUZAI runtime.

It must not expose:

- llama.cpp inference endpoints;
- SearXNG internal endpoints;
- local file-upload APIs;
- Piper TTS runtime endpoints;
- private repository credentials;
- private Git-RAG repositories;
- internal service addresses;
- server-side session or application secrets.

The demo may use static HTML, CSS and local JavaScript for browser-only interactions.

See [DEMO.md](DEMO.md) for the detailed architecture and safety rules.

Check the main demo:

```bash
curl -I https://kuzai.org/demo/
```

Check GIT-RAG demo:

```bash

```

Check Custom LLM demo:

```bash

```

Check Custom LLM editor demo:

```bash
curl -I https://kuzai.org/demo/modules/custom-llm/editor.html
```

Expected result:

```text

```

Static demo JavaScript should be reviewed for accidental network or persistent-storage access.

Typical checks:

```bash
grep -RniE 'fetch[[:space:]]*\(|XMLHttpRequest|WebSocket|EventSource|127\.0\.0\.1|localhost' public/demo
grep -RniE 'localStorage|sessionStorage|indexedDB' public/demo
```

Any intentional browser-state behavior must be reviewed explicitly.

## CURRENT DEPLOYMENT MODEL

- Git root is the production site root.
- Apache serves only the `public` directory.
- HTTPS is enabled with LetsEncrypt.
- HTTP redirects to HTTPS.
- Sensitive paths are blocked.
- GitHub is the deployment source of truth.
- Production synchronization uses fast-forward-only pulls.
- The public application demo is frontend-only and isolated from the private KUZAI backend.
